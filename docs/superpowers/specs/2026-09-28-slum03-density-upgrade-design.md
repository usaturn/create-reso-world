## 1. 目的と承認範囲

ユーザーは保存・別名バックアップ・Resonite再起動・保存ワールド再読込・ResoniteLink有効化を実施し、「slum02より見た目がチープ」「街区内のオブジェクトが全般的に少ない」と報告した。

会話で承認された方向は、**中央の活動床と歩行ルートを維持し、slum02の密度と作り込みを最低限の参照水準として、街区全体を充実させる**こと。建物・増築・店先の連なり、配管・配線等の中規模設備、商品・生活小物・廃材の順で厚みを作る。小物だけの散布やネオンの追加で代用しない。

本書は原仕様を全面的に置き換えない。街区内の密度、近景ディテール、配置データと検証方法を具体化する追加仕様である。本書に明記しない原仕様D-01〜D-14の判断は維持する。原仕様の「空ワールドへの初回制作」という工程は終了しており、今回は保存済みの既存所有ツリーを更新する。

- 工場跡地全体を空き地にするのではない。中央を除く周縁帯には瓦礫を置けるが、出入口と主導線を塞がない。

## 3. 採用する方法

| 方法 | 効果と問題 | 判断 |
| --- | --- | --- |
| 小物・看板だけ追加 | 近景は増えるが、建物間の空白と街路の弱さが残る | 不採用 |
| 市場等の見せ場だけ高密度化 | 小さく検証しやすいが、歩くと他の区画の疎らさが目立つ | 代表区画の品質確認にのみ使用 |
| 街区全体を三層で充実 | 大きな量塊・設備・小物の役割を分け、地域ごとの生活圏を作れる | 採用 |

全体のブロックアウトを先に作り、代表的な廃墟・屋台・小屋で近景品質を確認してから、同じ品質を全域へ展開する。終盤に数を揃えて初めて見た目を確認する進め方は繰り返さない。

## 4. 配置と物量

### 4.1 初期ブロックアウトの配置目標

次の数は**背景を含まない街区内の独立した用途単位**の合計で、追加数ではない。既存オブジェクトを含む。窓、商品、柱、屋根の部品を1棟・1屋台として水増ししない。

| 用途 | 現状 | 初期設計値 | 主な配置 |
| --- | ---: | ---: | --- |
| 廃ビル・廃墟の建物単位 | 4 | 32 | 北・西を中心に、北東と東には低層の変種 |
| 小屋・独立した居住増築 | 2 | 28 | 南西の住居群、北西の隙間、東の裏手 |
| 独立した屋台 | 2 | 28 | 南の市場20基を中心に、左右の枝道に計8基 |
| ネオン店先 | 2 | 8 | 東の横丁6軒、南東の市場との接点2軒 |
| Yarol | 1 | 1 | 既存の北東敷地 |

合計97の主要用途単位を出発点とする。既存の大型屋台2基は保持し、新規屋台は主に幅2.5〜4 m・奥行3〜5 mの単位を組み合わせる。新規の建物は主に幅・奥行8〜14 m、小屋は4〜7 mを基準に、路地と用途に応じて調整する。新規建物の高さは北・西で10〜30 m、東の視線に関係する帯では4〜12 m、小屋は3〜6 mを基準にする。既存の大きな建物をこの寸法へ無理に縮小しない。

これらの数を「slum02と同じ密度の証明」とはしない。面積倍率による単純な全種類2.25倍や、高層塔リングの再現もしない。密度と作り込みの最終判断は区画別・歩行視点別の比較で行う。通路や視線と両立しない場合はブロックアウト工程で配置案を修正し、数を減らす必要があれば理由と代案をユーザーに提示する。生成器が黙って間引いて完了にしない。

### 4.2 地区ごとの構成

- **北・西の廃墟帯:** 中層の躯体、崩れた低層部、後付け小屋を重ねる。独立した箱を等間隔に並べず、荷捌き・壁沿い設備・短い横道を伴う小さな建物群にする。北壁の文字と北の巨大建築を隠す連続壁は作らない。
- **南西の居住帯:** 屋根の高さ・材料・向きを変えた小屋群。玄関前、共同設備、雨水処理、生活小物を伴わせる。主導線から行き止まりと出口を判別できる配置にする。
- **南の市場:** 対面する店列と天幕の連なりを作り、左右に枝道と荷捌き場を設ける。元の南北3 m通路を通れることを最低条件とし、商品の張り出し後も人が歩ける有効幅で判定する。ARの見せ場は主文字を邪魔しない。
- **東の横丁:** 店先、低層の裏手、設備壁、縦看板を交互に並べる。東向きの横道を塞いで森を隠さない。北東はYarolの敷地・入口を主役にし、新規建物で覆わない。
- **中央周縁:** 大きな崩落塊、鉄骨・機械残骸、中小の廃材を大小の塊として集める。中央床と出入口には粒を散らさない。床のひびや汚れは段差を作らない表面表現とする。

正確な全座標・向き・占有形状は、実装の最初のブロックアウトで共通Layoutに固定する。この仕様書に別の座標表を複製しない。既存の重要アンカーと主導線は保持し、新しい一意キーの配置を加える。

### 4.3 密度を数以外でも確認する

`density-report.json` に次を記録する。背景・広告用部品・scatter粒は主要用途の数と分ける。

1. 用途別・地区別の配置数、変種、地上占有面積。
2. 建物・屋台・小屋等の占有の和集合面積。区画をまたぐものは交差部分だけを各区画へ配分し、二重加算しない。
3. 壁・店先・設備のある街路区間と、何もない区間。基幹ルートに沿って測り、意図した活動床・広場入口・森への見通しは用途付きの空間として区別する。
4. 散布物の粒数とは別に、どの建物・店・生活拠点に設備と小物が属するか。
5. 既存版との差分。主要用途だけ増えて近景ディテールが減っていないかも確認する。

居住・市場・横丁としてLayoutに指定したルートでは、20 mを超えて両側に街路要素がない区間を検出対象とする。道の中心線から左右各10 mの帯内にある、地上0〜8 mの建物正面・店先・小屋・設備群の評価後占有範囲を道の長手方向へ投影し、両側とも投影がない連続区間を測る。幅・高さ各1 m未満の小物、床、細い配線、背景はこの判定の街路要素に数えない。これは視覚的な連続性の一次検査で、画像の代替ではない。

活動床や景観用の開口を一律に埋めず、意図した空間は理由・範囲をLayoutに記録して限定的に除外する。道路・橋はこの密度指標の対象ではない。恣意的な広範囲除外で検査を通さない。北・西だけに集中させ、南・東を現状のまま残す案は受け入れない。

## 5. 一つ一つの作り込み

### 5.1 建物と増築

廃墟は少なくとも6系統の形状変種を用意する。厚いスラブ、深い窓、柱梁、崩落部、後付け外装を組み合わせ、単なる色・回転の違いを変種として数えない。歩行者が近づく正面・側面に、奥行きのある開口、部材の接合、破損の理由が読める形を持たせる。

足場、外階段、配管は取り付け先を持つ。今回の階段は背景的な外観要素であり、新たな探索可能階を約束しない。上れそうな階段が必須導線を邪魔したり、見えない床への移動を誘ったりする配置は避ける。建物内部を全階作ることはしない。

### 5.2 屋台・店先・小屋

- 屋台は電子部品、工具、義肢・機械部品、再生機材等の少なくとも4用途。1基ごとに2段以上の展示面、少なくとも12点の読める商品形状を基本とする。同じ箱12個で代用しない。
- 商品は基板の厚み・部品、工具の握り、モニターの枠と画面、ケーブル束等が1〜3 mの距離で区別できる形にする。小さすぎる形を数だけ増やさない。
- 天幕には厚み・垂れ・留め方、屋台には脚・筋交い・棚・背面収納を持たせる。
- 小屋は少なくとも4系統。材料の重なり、戸口、換気、雨樋、生活道具を持ち、地面に置いただけの単色箱を不可とする。
- 店先8軒は看板を色違いにするだけでなく、入口・シャッター・庇・照明・壁設備の構成を変える。非露骨な環境表現に限定する。

### 5.3 設備と生活感

配管、配電箱、室外機、タンク、メーター、排水、ケーブル、照明の取り付け金具を、用途と接続先を持つまとまりとして置く。主要な各建物群には壁面設備と生活・作業の痕跡を両方持たせる。

頭上設備は最低12の独立した経路・支持点のまとまりを初期目標とする。線分の分割数を件数にしない。既存の上空設備を保持し、荷重を支える柱・壁・金具からつなぐ。中央の上方3 mと経路の有効空間を侵さない。

瓦礫は大・中・小の比率とまとまりを調整し、slum02の堆積感を参照する。粒数506のコピーを合格条件にしない。機械残骸・鉄骨・コンクリート塊が判別でき、中央床へ散らばらないことを優先する。

### 5.4 素材・明暗

Cyberpunk、brutalist、dark-grittyの既存方向を維持する。コンクリート、塗装金属、錆、布、木、ガラス等を用途に応じて区別し、雨だれ・油・欠けを原因のある場所へ置く。全表面に同じノイズを掛けない。

近景の凹凸、AO・頂点カラー等による接触部の読みやすさ、素材間の粗さ・明度差を確保する。画像テクスチャを新たな必須依存にせず、形状不足を暗さや発光で隠さない。屋台とYarolは暖色、ARは冷色、横丁は赤紫の局所アクセント。光源を増やす場合も所有配下に限定し、全店に影付きライトを付けない。

## 6. 生成・データ設計

既存の `Layout → 区画生成 → Blender評価／export → pipeline` を拡張し、別の生成系や汎用都市エンジンは作らない。

| 責務 | 既存の主な場所 | 改善内容 |
| --- | --- | --- |
| 配置と制約 | `layout_district.py`、`layout.py`、`types.py`、`spatial.py` | 追加アンカー、地区・用途・変種・取り付け先・意図した空間の記述、配置物同士の干渉と分布検証 |
| 主要形状 | `ruins.py`、`shacks.py`、`stalls.py`、`nightlife.py` | 近景変種、用途別商品、接合と破損、主要単位の独立編集 |
| 設備・散布・素材 | `overhead.py`、`plaza.py`、`gn_scatter.py`、`materials.py`、`vcolor.py` | 取り付け先付き設備、除外付きの塊状散布、材質と接触部 |
| 評価と証跡 | `verify_assets.py`、`preview.py`、`delivery.py`、`pipeline.py` | 評価後の密度・境界・近景ディテールの証跡、カメラ、資源差分 |

責務が大きくなる箇所はslum03内の小さな専用モジュールに分ける。既存の区画登録・書き出し規則は再利用する。新しいメタデータは一箇所で定義し、保存Layoutを全工程へ渡す。既存の保存Layoutも読み取れるようにし、旧候補が今回の新しい密度条件を満たすとは判定しない。既定シード `260927` を維持する。

既存キーを番号の振り直しで変更しない。追加キーは地区と用途が読める一意な名前にする。各部品の乱数は配置順の変更で既存物の外観が全面的に変わらないように分離する。再利用するslum02の部品は必要分だけslum03内へ移し、実行時import依存を作らない。

1棟・1小屋・1屋台等の独立物を原則1メッシュにする。動かない商品・ボルト等は所有する屋台や設備にまとめ、微小な部品ごとにSlot／Rendererを増やさない。別に編集する設備群と、別に動く広告は分ける。メッシュを結合しても、密度レポートでは用途単位と内包するディテールの違いを保持する。

### 空間検証

- 既存の活動空間・主導線に加え、追加した枝道・店先の有効幅を検証する。主導線を変えず、必要な枝道を追加の保護領域として扱う。
- 回転後の範囲と、屋根・庇・商品・鉄筋等を含む評価後形状で検証する。
- 配置物間の意図しない貫通を検出する。壁付け設備・増築等の接触は、取り付け先と限定範囲を明記し、全体的な衝突検査免除にしない。
- AABBで開口を表せない門・天幕・既存の橋／検問は、実形状とコライダーの通路を別途検証する。大きな包含箱だけで通行可否を決めない。
- 東の森林への既存視点と、北の巨大建築・北壁文字の見え方を再確認する。新しい建物のAABBだけで視覚合格にしない。

## 7. 制作・検証の段階

### Gate A: 街区全体の配置

新しいLayout、密度レポート、真上図、目の高さ約1.6 mの北西・南西・市場・東横丁の視点を作る。中央床を避けた密度、歩行の連続性、地区ごとの違いが見えることを確認する。原版と同じ視点の比較も残す。この段階で配置違反や明らかな疎らさがあれば、全区画の細部制作へ進まない。

### Gate B: 代表区画の近景品質

既存の用途に対応する廃墟・小屋・屋台を各1単位以上、周囲の設備と小物まで仕上げる。1〜3 mの近景と街路側の中景を確認し、slum02の同用途の形状ディテールを下回らないことをチェックする。

slum02の資料と比較する際は視距離・画角・明るさの条件を併記し、異なる条件の画像から厳密な優劣や負荷改善を断言しない。slum03の原版とのオフライン比較は同じカメラ・同じ診断用照明条件で作る。

さらに、実装計画承認後のこの段階で、代表単位と直接付随する設備だけを更新する完全な宣言候補を作る。その他の既存内容は保持し、別root/stateや全体の未完成ブロックアウトへ置き換えない。候補固有の保存Layout・出力・報告を対応させ、対象のテスト・資源検査・全diffレビュー後、既存所有ツリーへ限定反映する。範囲外の変更がdiffに出る場合は止める。Gate Dと同じ再観測・同一入力再applyの安全手順を適用する。

ユーザーが実機で代表区画を確認し、見た目の方向が適切だと判断するまで全域へ量産しない。自動captureが利用できなくても目視確認を依頼できるが、Blender画像だけで実機の確認済みにしない。これは今回の再作業リスクを抑える明示的な確認地点とする。

### Gate C: 全域への展開とオフライン検証

代表品質を維持して全区画へ展開する。純粋な配置・幾何・集計・宣言処理はTDDで進め、実際のBlender評価・exportを別に検証する。少なくとも以下の回帰を含める。

- 現状の「廃墟4・小屋2・屋台2」の疎な候補は新しい密度検査で不合格になる。
- 1ヶ所に集中、重複配置、背景の数だけ増加、カウントだけ増やした空アンカーは合格にできない。
- 中央・主導線・追加枝道の侵入、孤立した入口、Yarol前の閉塞を検出する。
- 同じ保存Layoutとシードから、独立した出力で配置・形状が再現する。
- UV0・追加UV・頂点カラー、法線、文字判読、駆動対象と固定文字の分離を維持する。
- 実際の生成件数から宣言・報告の件数とhashを検証する。旧150メッシュ／339 Slotsを新しい期待値に固定しない。

`uv run pytest`、配置検査、実際のexport済み資源検査、レイアウト検査を通してから全域のlive候補を決める。実行コマンドと成果物名は実装計画で確定し、既存の生成ディレクトリを上書きしない。Gate Bの部分改善候補と、全域の密度条件を満たす候補の合否は分けて記録する。

### Gate D: 実機での表示・歩行・更新の安全性

既存所有ツリーとstateを再観測し、diffの全対象・理由を確認してから更新する。同一宣言・stateの再applyで書き込み・importゼロを確認する。apply失敗時は途中状態を保存し、観測と再diffを行い、盲目的に再実行しない。

実機では以下を**人の目の高さ**で確認する。俯瞰図だけで代用しない。

| 視点・動線 | 合格条件 |
| --- | --- |
| 中央から北西・西 | 活動床の開放感と周縁の濃い街並みが両立。北壁文字が読める |
| 南西の生活路地 | 小屋・設備・生活道具がまとまり、単独の箱が点在する状態ではない |
| 市場入口・市場内部 | 店列、商品の厚み、天幕、横道が見える。主コピー・通路を妨げない |
| 東横丁から東向き横道 | 店先が連続しつつ、道路と森林への開口が残る |
| Yarol前・検問・橋 | 入口と既存経路を保持し、増築で迷路や障害物を作らない |
| 西・南の街区境界 | 近景から既存背景へ街が続き、局所的な密集だけで他を放置していない |

新しいカメラは名前だけで被写体を保証しない。目の位置・向き・画角・対象を記録し、市場を評価する画像には実際に店列と商品が写っていることを確認する。暗すぎる画像、近い壁で遮られた画像、対象が写っていない画像は証拠として不採用とする。診断用照明によるBlender画像は実機画像と明確に区別する。

共有スクリーンショットフォルダがない現状では自動captureの成功を前提にしない。ユーザーの実機画像または目視・歩行報告を得る。画像や歩行確認がない項目は未確認のまま残す。最後に、ユーザーが「街区全体の密度・作り込みがslum02を下回らない」と判断することを視覚受入条件にする。

## 8. 負荷と既知の未達条件

三角形・頂点・メッシュ・素材・draw section・透明面の重なり・光源／影・コライダー・駆動を区画別に記録する。旧slum03とslum02の資源量を参照するが、473,164三角形へ合わせることや旧86,940へ収めることを目的にしない。

近景の輪郭と奥行きを先に確保し、見えない内部、同じ場所の重複面、過剰な透明層、不要な微細Rendererを減らす。評価のために近景ディテールを削る場合は見た目を再確認する。全景のカリング改善やFPSを測定せずに性能向上・性能保証を主張しない。

| 既知事項 | 今回の扱い |
| --- | --- |
| strict auditの `ITEM_GRABBABLE_MISSING` | 別の受入判断が必要。自動的にpassへ変えない |
| 森林奥の隙間 | 今回対象外の既知残件。密度改善の完了と区別 |
| 保存・再読込 | 旧版の操作はユーザー確認済み、新版の保持成功ではない。新版で必要ならユーザーに操作を依頼 |
| 描画・歩行 | 構造テストやオフライン画像で代用しない |

今回の密度改善が受け入れられても、これらが残ればワールド全体の完全納品とは報告しない。
