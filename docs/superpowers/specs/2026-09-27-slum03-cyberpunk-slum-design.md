# slum03 サイバーパンク・スラム街 設計仕様

- 日付: 2026-09-27
- 対象: `usaturn/create-reso-world` の新規プロジェクト `slum03/`
- 状態: 会話による設計承認済み。本書のレビュー待ち。実装計画・モデル生成・ライブ反映は未着手。

## 1. 目的と成功条件

アバターが自由に動ける工場跡地を中心に、密度の高い廃墟・ジャンク屋台・小屋・ネオン横丁が広がるサイバーパンクのスラム街を作る。街区内の生活感と、北側の巨大都市、東側の森林の対比を重視する。

`slum02` の生成・出力基盤と有用な部品は再利用するが、単純な拡大版にはしない。街区配置、AR広告、道路・橋・検問、周辺景観を新しく設計する。`slum02` のソース・生成物・ライブコンテンツは変更しない。

成功条件は、寸法やオブジェクト数が合うだけでなく、中央で歩き回れること、広告に立体的な未来感があること、北・東・西・南それぞれに意図した景観が見えること。BlenderのプレビューだけをResoniteでの最終確認とは扱わない。

## 4. 座標と空間設計

### 4.1 基準

寸法はメートル。Resoniteローカル座標は東=+X、上=+Y、北=+Z。中央活動床の仕上げ面をY=0とし、街区中心をX=Z=0にする。生成の既定シードは `260927` とし、変更はレイアウト設定に明示して意図した別案として扱う。

Blender側はZ-upになるため変換を一箇所に集約する。再利用候補にはXZY変換と面の巻き順反転があるが、無検証でコピーせず、法線・UV・回転・コライダーが同じ配置を表すことをテストする。

以下の座標範囲はレイアウト生成の基準値。詳細形状や境界処理の寸法は同じレイアウトデータで管理し、BlenderとResonite宣言に重複した定数を持たせない。

| 対象 | X範囲 | Z範囲 | 条件 |
| --- | --- | --- | --- |
| 街区本体 | -60〜60 | -60〜60 | 外側の道路・背景を含めて120 mと数えない |
| 工場跡地 | -20〜20 | -15〜15 | 40×30 m |
| 中央活動床 | -16〜16 | -11〜11 | 32×22 m。床以外の障害物なし |
| 西側歩道 | 60〜66 | 道路の全歩行区間 | 街区に隣接 |
| 東側車道 | 66〜90 | 道路の全歩行区間 | 幅24 m |
| 東側歩道 | 90〜96 | 道路の全歩行区間 | 森の手前 |
| 森の前縁 | 100以東 | 川の南岸より南 | 歩道と区別する非歩行領域 |
| 川 | 東西に背景まで延長 | 78〜112 | 水面幅約34 m |
| 橋 | 60〜96 | 72〜118 | 車道と両側歩道を連続させ、両岸に接続 |
| 検問 | 道路沿い | 66〜72付近 | 南側橋詰。歩ける開口を残す |

道路は街区南端の先から橋北端の折り返しスペースまで連続させる。歩行領域の南北端はレイアウトに明示し、欄干・護岸・ゲート脇構造などで背景へ抜けない境界を作る。検問を閉鎖して橋に到達できなくする構成は採用しない。

### 4.2 中央の工場跡地

- 中央32×22 mの床を平坦かつ連続した活動スペースとする。ひび、油染み、焼け跡は表面表現で付け、段差・穴・機械基礎・鉄筋・瓦礫を置かない。
- 周囲約4 mの帯と跡地の外側に、コンクリート塊・鉄骨・トラス断片・機械残骸・廃材を集める。大・中・小の形と密度を混ぜ、均等な粒の散布にしない。
- 主な出入口は東・西・南。幅3 m以上を確保し、屋台通りと東の道路につながる。中央領域だけでなく、出入口を結ぶ導線もscatter禁止領域に含める。
- 瓦礫の中心点だけでなく、回転・スケール・突出する鉄筋を含む形状の占有範囲で除外判定する。
- 中央活動床の上方3 mも、広告・ケーブル・吊り下げ物のない活動空間として確保する。

### 4.3 北の工場壁とスプレーアート

- 北縁の瓦礫帯に残存壁を置く。基準は中心X=0、Z=14.5、幅約36 m、厚さ約0.8 m、高さ約10 m。中央活動床には張り出さない。
- 厚いコンクリート、付け柱、打継ぎ、崩れた上端、露出鉄筋を持つ。正面中央には文字を読める連続した面を残す。
- 南向きの面に、正確に `稲垣は絶対マカぶる` と表示。赤の塗り、黒の縁取り、塗料の垂れと周囲の吹き付け跡を付ける。発光文字にはしない。
- `slum02` のOFLフォントはライセンスと一緒に再利用可能。全使用文字の収録とメッシュ化後の向き・判読性を確認する。
- 壁と文字は個別編集可能な独立オブジェクトにする。南側の活動空間から正しく読めることを検証する。
- 壁の東西端に迂回できる余地を残す。東側の旧壁配置は採用しない。

### 4.4 街区内の用途

- **北・西・北西:** 廃ビルと廃墟を主とし、トタン増築や小屋を隙間に混ぜる。各建物をランダムに回すだけでなく、路地、荷捌き、排水、取り付け構造が成立する配置にする。
- **南:** ジャンク屋台通り。対面する棚・天幕・商品を配置しても通路が狭まらないようにする。南側背景の屋根や看板に街が続く。
- **東:** 低中層の廃墟とネオン横丁。風俗店は数軒を散在させる。中央から東への横道を確保し、森への視線を建物の壁で閉じない。
- **北東:** Yarol。敷地の目安はX=43〜59、Z=40〜54。入口は東向きで、街区側歩道へつながる。内部に入れる動線・室内コライダーは作らない。
- 建物・屋台の数は密度の調整値とし、無根拠な個数を達成するために通路を埋めない。必須用途の存在と占有範囲をレイアウトの検証対象にする。

### 4.5 周辺景観

**北:** 川の向こうに高さ80〜200 m級の高層群、その奥に500〜900 m級のアーコロジーを複数置く。アーコロジーは最低3棟、段状の巨壁、巨大な空隙を持つ門状構造、連結塔の3種類のシルエットを基礎とする。高さだけでなく幅・奥行き・居住区・渡り廊下も巨大にする。

配置距離は見かけの大きさと重なりを見て調整する。北側工場壁の上または切れ目から巨大建築が読めることを条件とし、壁の向こうに置いたという座標だけで合格にしない。

**東:** 道路の向こうに広い森林。近い樹木は幹と樹冠が立体として読め、奥は樹冠の層とシルエットで連続感を出す。自然な緑と褐色を用い、ネオン化しない。東向き横道と歩道から木々が見えることを優先する。中央の全地点から森全体が遮りなく見えることまでは要求しない。

**西・南:** 低中層の廃ビル、重なる屋根、増築、路地、遠い看板で街区の続きを表現する。近景から遠景へ形状を簡略化し、世界の端や既定地面を見せない。背景は非歩行領域とし、見えない内部や細かなコライダーを作らない。

`slum02` の全方位高層リングと、全方向のレイを必ず建物に当てる遮蔽試験は移植しない。北の巨大都市・東の森への視線を残し、西・南では街の連続感を検証する方向別の条件に置き換える。

## 5. AR広告の造形と動き

### 5.1 3系統

| 系統 | 造形 | 主な配置 | 動き |
| --- | --- | --- | --- |
| 立体商品ホロ | 義眼・義肢・部品の立体、分割リング、前後に離れた注釈 | 屋台通りなどの見せ場 | 商品またはリングをゆっくり回転。主文字は固定 |
| 層状情報広告 | 大きな主コピー、離れた補助情報、途切れた発光輪郭、薄い走査パターン | 壁面、店舗上部、縦長広告 | 走査線・補助帯をゆっくり移動 |
| 曲面リボン | 薄い湾曲帯、記号、分割された光の弧 | 路地入口と一部の上空 | 補助パターンを流し、帯全体の激しい回転はしない |

3系統を混在させる。大きな立体ホロは見せ場に限定し、小型の層状広告を各所に展開する。投影台・壁付けプロジェクター・取り付け金具を造形し、全広告を分厚い額縁付きの板に戻さない。

### 5.2 共通条件

- シアンとマゼンタを主軸にライム・琥珀を差し色として使う。各広告は主色1色と補助色程度に整理する。
- 輪郭、立体形状、異なる奥行きの表示層を主役にし、大面積の半透明面を何重にも重ねることに依存しない。
- 主コピーは想定視距離で読める大きさと向きにする。補助情報を増やして主コピーを埋没させない。
- 動く部品の可動範囲まで含めて、活動空間・歩行経路・重要な視線を侵さないことを確認する。
- 高速点滅、全広告の同期した明滅、視界を横切る高速移動を使わない。
- BlenderのGeometry NodesをResoniteの実行時グラフとして扱わない。動きは確認済みのResonite標準駆動コンポーネントを優先する。
- 半透明素材・駆動型は現接続先のReflectionで確認する。旧環境の `FresnelMaterial`、`Spinner`、`Panner2D` などは調査候補であり、現環境での動作保証ではない。

## 6. 建築・小物・素材

- **ブルータリスト建築:** 厚い床スラブ・梁、深い窓、少数の大きな量塊、型枠や打継ぎの構造。崩落面、鉄筋、片持ち部、足場や階段は取り付き方を説明できる形にする。
- **ジャンク屋台:** パイプフレーム、シート・トタン屋根、棚、部品箱、基板、モニター、ケーブル、工具、義肢パーツ。手の届く範囲の小物は近景として形を読めるようにする。
- **小屋:** トタン、ベニヤ、シート、パレットの寄せ集め。支点、留め方、雨水処理、換気、生活道具を局所的に表現する。
- **Yarol:** 暗いコンクリート、控えめな店名ネオン、暖色の入口と窓越しの雰囲気。外観の見せ場として作る。
- **経年劣化:** 窓下・排水口・打継ぎに雨だれ。湿る継ぎ目や剥がれた塗装に錆。角・衝突面に欠け。触れる箇所に摩耗。保護面や手入れされた表示には比較的きれいな部分を残す。
- **照明:** 屋台・Yarolは琥珀色、ARは冷色、風俗店は赤紫を局所利用。slum03所有配下の光源に限定し、既存の空や全体照明は変えない。

素材の基本は再利用可能な頂点カラーと対応するネイティブ素材・手続き模様とする。画像テクスチャを必須にせず、近景の重要な形状はメッシュで保持する。画像が必要になった場合は、ホスト側への転送経路を先に検証し、出力しただけで表示できるとみなさない。

UVは近景の文字、長い帯、曲面の歪みを優先して確認する。render-activeなUVをUV0として維持し、追加UVを勝手に削除しない。共有部材では密度を揃え、重要面は適切に解像度を配分する。ワールド全体を一枚の巨大なテクスチャへ押し込めない。

## 7. 実装の構成

### 7.1 独立したプロジェクト

実装開始の承認後、リポジトリルートの `scripts/new-world.sh slum03` で雛形を作る。以後のワールド作業とテストは `slum03/` をcwdとして行い、ルートとプロジェクト両方の `AGENTS.md` を適用する。

想定構成:

```text
slum03/
  AGENTS.md                       # 所有キー、ルート、state、テスト方法
  pyproject.toml / uv.lock
  assets/fonts/                   # 再利用フォントとライセンス
  modeling/slum03/
    layout.py                     # 寸法、配置、領域、シード、視点、検証
    geometry.py / materials.py    # 独立した再利用部品と素材定義
    uv.py / vcolor.py / blender_io.py
    sectors.py                    # 区画と生成器の登録
    build.py / preview.py         # Blender構築と反復用プレビュー
    pipeline.py / postprocess.py  # 出力統合とネイティブ宣言
    (区画ごとの生成モジュール)
  content/slum03/
    layout.json                   # 配置の生成結果
    slum03.json                   # 統合した適用宣言
    bundles/                      # 区画ごとの出力
  artifacts/slum03/
    *.blend / *-report.json
    previews/
    delivery-report.json
    timing.md
  tests/slum03/
  .resoloop/slum03/state/slum03.json
```

この構成は責務の分離を示す。細かなファイル分割は実装計画で確定するが、配置・形状・Blender依存部・ネイティブ反映を一つの巨大ファイルへまとめない。

### 7.2 再利用境界

`slum02/modeling/slum02/` の幾何部品、UV、頂点カラー、Blender橋渡し、区画ビルド、バンドル統合を調査して必要な部分だけ `slum03` 内へ移す。共有ライブラリ化を目的としたリポジトリ全体の変更はしない。

- 実行時に `modeling.slum02` へ依存しない。
- 旧所有キー、スロット名、出力先、state、セッションID、spray文字列を持ち込まない。
- 旧レイアウトの80×80 m、20×20 m、全方位高層リング、東側工場壁を引き継がない。
- 旧 `build.py` のシーン初期化は、新しく生成する専用Blenderシーンだけに限定する。ユーザーの既存 `.blend` に一括削除処理を実行しない。
- 再利用するテストは仕様に合わせて見直す。旧仕様を満たすことを新仕様の合格根拠にしない。

### 7.3 データの流れ

```text
固定シード・寸法・配置制約
  → 共通レイアウト + 配置検証
  → 区画ごとの形状生成 / Geometry Nodes
  → 編集可能なBlenderソース + 静的出力コピー
  → プレビューとメッシュ・UV・資源レポート
  → resoloopの標準エクスポート
  → 素材・コライダー・光源・AR駆動を含む宣言の統合
  → Reflectionを含む差分確認
  → 適用 → 実機検証 → 同一宣言を再適用して無変更確認
```

共通レイアウトに、安定したID、区画、用途、座標、寸法、向き、歩行/背景の区別、占有範囲、出入口、scatter禁止領域、視線検証用の視点を持たせる。Blenderとコライダー生成は同じデータを読む。

### 7.4 区画と責務

1. 地盤・街路・中央床。
2. 工場跡地・北壁・graffiti・周縁の瓦礫。
3. 廃ビル・廃墟・小屋・頭上の配線や配管。
4. 屋台・ネオン横丁・Yarol。
5. AR広告の静的部品と駆動対象。
6. 東側道路・護岸・川・橋・検問。
7. 東側森林。
8. 北の高層群・アーコロジー、西・南の背景街区。

一つの区画が重い場合は地理・責務でさらに分割する。1棟、1屋台など後から編集したい独立物を1メッシュにまとめ、街区全体を1メッシュにしない。別々に動く広告部品は別オブジェクトにし、命名と階層で一つの広告にまとめる。

### 7.5 指定スキルの適用先

| スキル | 適用 |
| --- | --- |
| blender-modeler | 寸法、ブロックアウト、ピボット、編集元と出力コピーの整理 |
| hard-surface | 屋台フレーム、投影機、検問設備、機械残骸、取り付け金具 |
| prop-artist | 商品、工具、容器、生活小物、Yarolの外観小物 |
| uv-workflow | 文字・帯・曲面のUV、密度、エクスポート後の保持 |
| procedural-modeling | 建物変種、道路・護岸、配線、再現可能なパラメータ |
| geometry-nodes | 除外領域付き瓦礫scatter、森林の配置・変種。固定シードと評価結果の確認 |
| sci-fi-punk-worlds / Cyberpunk | 密集した生活圏、縦方向の表示、巨大都市と足元の対比 |
| brutalist-mood | 建築量塊、深い凹み、構造と人間スケール |

Geometry Nodesの編集可能なグラフ・入力・元部品を保存し、出力コピーでのみインスタンスを実体化する。除外領域は点の配置だけでなく評価後の形状でも検証する。ノード名・ソケット・Blender APIは導入済み版のRNAやメタデータで確認する。

## 8. Resoniteへの反映と所有境界

- 所有キー: `slum03`。所有ルートスロット: `Slum03_Slum`。
- state: `.resoloop/slum03/state/slum03.json`。他プロジェクトのstateをコピーしない。
- ユーザーが選んだ別の空ワールドへの接続を確認してから作業する。接続先未設定時はresonite-buildの自動探索に従い、候補が複数ならユーザーに選択してもらう。現在の接続先に対してdoctorを実行する。
- 「空ワールド」は所有範囲外の内容を削除してよいという意味ではない。`Root`、既定床、既存スロット、他プロジェクトの内容を変更しない。
- 川を地表より低く作るため、既定床が水面を隠す可能性を確認する。その場合は所有ルート全体の設置高さを調整し、必要な地盤・護岸を所有配下で作る。既定床を削除して解決しない。選定したルート変換を宣言とレポートに固定する。
- 未知の型・メンバー・enumは実機ReflectionまたはFlux-SDKメタデータで確認する。スロットやIDは現セッションで再観測する。
- ライブ変更はresoloopだけで行う。適用前に `diff --brief` の対象と理由を確認し、適用後は同じ入力・stateで再適用して書き込みゼロを確認する。
- 最終的に所有ルートのitem auditをstrictモードで実行し、外部参照と資源参照を確認する。システムのフォントなど許可が必要な外部参照は、確認済みの型・メンバー単位で列挙する。広すぎる許可や未使用の許可で監査を通さない。保存・再読込による資源の保持を確認できない場合は、その項目を未確認として報告する。
- 削除・pruneは対象がslum03所有配下の検証済みIDであることを確認し、削除候補を事前にレビューする。所有権が不明な対象をadoptしない。
- `.devcontainer/resoloop.lock` を版管理の正とし、導入済み版と同梱スキルの整合性を確認する。このタスクで版を更新しない。

## 9. 品質・負荷・検証

### 9.1 自動検証

| 領域 | 必須の検証 |
| --- | --- |
| 寸法 | 街区120×120 m、工場40×30 m、中央32×22 m、車道24 m、歩道各6 m |
| 活動空間 | 中央と上方3 mに障害物なし。評価後の形状とコライダー双方を検査 |
| 導線 | 東西南の出入口、屋台通り、東の道路、橋、検問が連続。幅3 mの主導線を維持 |
| 工場壁 | 北側にある、中央から読める南向き、文字列完全一致、旧東壁なし |
| 景観 | 西・南の背景あり、北の高層群と最低3棟のアーコロジー、東の森と指定視点からの可視性 |
| 配置 | 生成物と宣言の座標が一致。名前・IDが一意で固定シードに再現性がある |
| 所有 | slum03キーとstateのみ。slum02へのimport、旧セッションID、旧出力先の混入なし |
| メッシュ | 法線、意図しない欠損、接地、UVの歪み、UV0・追加UV・頂点カラーの保持 |
| AR | 動く部品の可動範囲、主文字の固定、素材参照と駆動先の解決 |
| 適用 | 宣言の検証、想定外の差分なし、再適用で書き込みゼロ |

純粋な配置・幾何・宣言処理はBlenderやライブ接続なしでテストできるようにする。GNで実体化した形状やスケール変更後の境界は、Blender側の評価結果をレポートとして読み込み、再度検証する。

### 9.2 視覚・歩行の確認

- 中央の複数地点と目の高さ約1.6 mから、床の活動空間、北壁の文字、北の巨大建築を確認する。
- 東向き横道・東側歩道から森林の幹と樹冠が読め、道路の先に橋と検問が見えることを確認する。
- 西・南では背景街区への連続感があり、空白の地平線や背景カードの端が目立たないことを確認する。
- AR3系統を斜めから見ても立体・表示層・曲率が読め、昼の環境光でも主コピーが判読できることを確認する。
- 工場跡地→屋台通り→東側歩道→Yarol前→検問→橋の歩行を確認する。見た目の床と衝突面のずれ、欄干の抜け、通路を塞ぐ看板がないことを確認する。
- セクタ別のBlenderプレビューは反復用。実機キャプチャが取得できない場合は、ユーザーの目視・歩行確認が必要な項目を明記し、最終検証は未完了として扱う。

### 9.3 描画資源

メッシュ数、三角形・頂点数、マテリアル数、サブメッシュ数、テクスチャ寸法・推定メモリ、透明面の重なり、光源・影付き光源、コライダーと駆動コンポーネント数を区画別・全体で記録する。

任意の丸いポリゴン数を達成するために重要な形状を削らない。近景の輪郭・接触影・視差へ寄与する形状は保持し、背景の見えない内部、過剰な透明層、役割のない微細形状を減らす。共有メッシュ・素材の利用は調査するが、実際の描画呼び出し削減を測らずに性能改善と断言しない。

環境依存のFPS保証は置かない。使用環境と測定可能な指標、必要な調整、残る負荷上の懸念を納品レポートに記録する。

### 9.4 失敗時の扱い

- 配置違反、壊れたUV、未解決参照、実体化漏れがあれば該当区画を止め、ライブ適用しない。
- AO、画像転送、ホロ素材、駆動が利用できない場合に、静かな失敗や無断の見た目の格下げをしない。原因と代案を記録し、必要なら設計変更を確認する。
- apply失敗時は途中状態を観測してから差分を再確認する。同じ変更を盲目的に再実行しない。
- 旧 `slum02` での画像転送・キャプチャ制限は過去の観測であり、現環境の仕様とはみなさない。新しい接続先で再確認する。
