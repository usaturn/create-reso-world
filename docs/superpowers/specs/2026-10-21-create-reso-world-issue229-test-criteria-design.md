### 1. 新しい節（`AGENTS.md:18-33` を置き換える）

```markdown
## テストの採用基準

テストを書くのは、下の S に当たる項目だけである。テストごとに、確かめる項目が壊れたときにエラーで気付けるかで、次のどれに当たるかを決める。

- F 固定値（書かない）: リポジトリの文書・設定・一覧の今の値を写して照合するテスト。文書の文言・見出し・節（削除した旧ファイル・旧文言が無いことを含む）、SKILL.md の本文と frontmatter、ランチャー・手順名・モデル・版・tier・mount・環境変数・ファイルの一覧、リポジトリのファイルのハッシュ、設定ファイルの値を写したもの、スクリプトを実行せずに本文の文字列だけで判定するものが当たる。コードに入力を与えて出力と比べる単体テストの期待値と、SKILL.md の手順を取り出して実際に実行するテストは F ではない
- F∩S（例外として使ってよい）: F のうち、壊れてもエラーにならない損害を防ぐ固定値。安全な操作範囲・権限・凍結した履歴・利用者所有部分を守る固定値が当たる。例: 削除の範囲、誤った対象を操作しないために禁止するパス、資格情報の送り先、権限を決める設定値（SKILL.md の frontmatter を含む）、指示ファイルの読み込み指定、mount・unset する環境変数・gitignore の範囲の一覧、利用者所有部分や凍結した履歴のハッシュ。防ぐ損害と理由をテストに書く
- L 気付ける（テストしない）: テストが無くても、壊れたときに普段の利用か既存の検査で、エラーや明らかな異常として現れる項目。例外・トレースバック、メッセージ付きの非 0 の終了、import・構文・解析のエラー、argparse、pydantic の検証、型検査・ruff、コマンドやファイルが見つからない、`scripts/check-layout.sh` の失敗、同じ流れの後段（次のツール、git、gh）が必ず失敗する、初回の利用で明らかに動かない、などで現れるものが当たる。ヘルプの文面、オプションの解析、エラーで止まる経路の終了コード、ファイルの存在・実行権限・symlink、誤った入力で例外を投げることだけを確かめるテストも L。ただし、拒否が壊れると危険な操作がエラーなしに進むものは S
- S 気付けない損害（書く）: 壊れてもエラーにならず、気付かないまま損害が残る項目。誤っているがもっともらしい結果（失敗を成功と報告する、別の PR・ブランチ・リポジトリ・base を選ぶ、未検証の状態をマージする、記録を失う・上書きする）、データの消失、誤った対象の削除・上書き・破壊的な git の操作、秘密情報の漏れ、危険な操作の拒否（パスの脱出、権限・サンドボックスの境界）、環境の隔離（`GIT_*`・`HOME`）、競合の防止が当たる。実際に起きた、気付けない不具合の再発防止も含む
- D 重複（代表の 1 件にする）: S のうち、同じ守りを別の組み合わせ・層・ファイルで確かめるテスト。同じ守りは代表の 1 件にし、組み合わせを網羅しない。同じ実体を複数のパス（symlink など）で確かめない。拒否を確かめるテストには、正しく通る例を少なくとも 1 件残す（何でも拒否する実装で通らないように）。守りは、それを実装しているモジュールのテストに置く
- superpowers の TDD でも、S に当たらない挙動のテストはコミットしない。確かめは、ツールの実行や一時的なテストで行う。一時的なテストの置き場所は「コミットしないファイルの置き場所」に従う
- テストを書かないときは、ツールの実行、静的解析・型検査、構造の検査（構文・参照先の実在）、`git diff` の確認で代え、結果を報告する
- Plan の各 Task に、テストの要否と理由を書く。不要なら、代わりの検証を検証手順にする
- レビューでは、追加・変更されたテストがこの基準に反していないか確かめる。守りの不足だけでなく、基準に反して足されたテスト（書きすぎ）も指摘する
```
