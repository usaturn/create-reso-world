# 共通 RST 記述規則

全 profile に共通する構造と静的検査を定める。言語、文体、出力先、用語集、コード言語・図の選択、build 方針は選択した profile を読む。
入力と利用可能性の確認は [入力仕様](profile-interface.md)、template の選択は [文書種別表](document-types.md) に従う。

## ページと見出し

ページ先頭に `.. _page_label:` を置く。新規ページのラベルは原則ファイル名の stem とし、文書群の中で一意にする。
衝突するときは対象 project の命名に合わせて一意にし、無関係の既存ラベルを改名しない。
編集では既存ラベルを保持する。

| レベル | 装飾 | 用途 |
|---|---|---|
| 1 | 上下 `=` | ページタイトル |
| 2 | 下線 `=` | 節 |
| 3 | 下線 `-` | 小節 |
| 4 | 下線 `~` | 必要な場合の下位節 |
| 5 | 下線 `"` | 極力使わない |

上下線・下線の長さは見出しの表示幅以上にする。最終的な幅の調整は lint の最後で行う。
通常はレベル3までとし、深い階層は表やフィールドリストで表す。

## 参照とリンク

ページ間・節間は `:ref:` を使い、`:doc:` は使わない。これはこのスキルの執筆方針である。
ページ全体なら先頭ラベル、特定の節なら節の直前に付けた明示ラベルへ直接参照する。
節ラベルは `{ページラベル}_{節の識別子}` を基本とする。
ページへの参照に「の○○節」と文字を添える形で代用しない。

```rst
.. _queue_check_results:

結果確認
========

処理結果を確認する

.. 参照元では次のように記述する

詳細は :ref:`結果確認 <queue_check_results>` を参照する
```

参照先の実在とラベルを確認する。ラベルを追加するために依頼範囲外のファイルを編集する必要があれば、不足作業として報告する。
外部リンクは匿名参照（末尾 `__`）を使う。

```rst
`Sphinx の参照記法 <https://www.sphinx-doc.org/en/master/usage/referencing.html>`__
```

## インライン記法とブロック

- インラインリテラル、role、名前付き参照、内部ターゲットの外側に境界スペースを置く。
  行頭・行末では余分なスペースは不要。日本語の句読点や括弧が隣接する場合も半角スペースを入れる。
- `**強調**` の前後にも半角スペースを入れる。強調は必要な箇所に絞る。
- literal block は導入文のあとに半角スペースと `::` を置き、空行を挟む。中身はその文脈から4スペース字下げする。
- directive は options と本文の間に空行を置き、本文の字下げを統一する。コード言語に応じた directive の選択は profile に従う。

```rst
``queue`` の値を **確認** する

内容を表示する ::

    printf '%s\n' queue
```

## 表とリスト

比較表は `.. list-table::` を使い、`:header-rows:` と `:widths:` を指定する。
セルの継続行はセル本文に揃える。

```rst
.. list-table:: 処理の状態
   :header-rows: 1
   :widths: 1 3

   * - 状態
     - 意味
   * - 待機
     - 処理の開始を待つ
```

定義的な情報はフィールドリストで示す。本文の継続行を最初の本文開始カラムに揃え、字下げを混在させない。
項目名が長い場合は本文を次行から4スペース字下げで始める。
`unexpected unindent` を避けるため、本文の途中で字下げを浅くしない。

```rst
:確認の目的:
    待機中の処理を特定する。
    処理の件数を確認する
```

フィールド内の literal block は、項目名の行を空にし、独立した `::` を4スペース、コードを8スペース字下げする。
`:項目: ::` と同じ行へ詰めない。単一行コマンドでも同じ構造にする。

```rst
:確認例:
    ::

        printf '%s\n' queue
```

手順の連番は `#.`、箇条書きは `-` を使う。箇条書きの入れ子は2スペース字下げする。
リスト内のブロックは項目本文の字下げを基準にする。

## 共通の静的検査

profile が確定した検査用 Python project の絶対パスを `LINT_PROJECT`、今回作成・編集した RST の絶対パスを `TARGET` として、ファイルごとに次を順に実行する。
対象ファイルの置き場所と uv project は別である。親 cwd の暗黙の project discovery に頼らない。

```sh
uv run --project "$LINT_PROJECT" wabun-rst-ulint inline-spacing --fix "$TARGET"
uv run --project "$LINT_PROJECT" wabun-rst-ulint strong-spacing --fix "$TARGET"
uv run --project "$LINT_PROJECT" wabun-rst-ulint sentence-breaks --fix "$TARGET"
uv run --project "$LINT_PROJECT" wabun-rst-ulint heading-width --fix --backup-suffix .bak "$TARGET"
```

| 順序 | 検査 | 対象 |
|---|---|---|
| 1 | `inline-spacing` | インラインリテラル・role・参照などの外側の境界スペース |
| 2 | `strong-spacing` | `**...**` の前後。単一 `*...*` は対象外 |
| 3 | `sentence-breaks` | 句点直後の改行とテキストブロック末尾の句点 |
| 4 | `heading-width` | 見出しの上下線・下線の表示幅 |

フラグなしは検出のみなので、作成・編集後は全段階で `--fix` を使う。
先行修正で見出しの幅が変わりうるため `heading-width` は必ず最後にする。
`--backup-suffix .bak` は書き換えがある場合の元ファイルを `<対象>.bak` に残す。
未編集のファイルを検査対象へ追加しない。profile が用語集の更新を認めており、今回その用語集も編集した場合は、その絶対パスにも同じ4段階を適用する。

実行コマンド、cwd、uv project、終了値、最終差分を確認し、失敗した検査や未実行の検査を成功として報告しない。
検査には `wabun-rst-ulint` を使い、旧 `scripts/check_rst_*.py` 等へ代替しない。
build の要否は profile の規則で判断する。
